# /implement-issue — מימוש issue

הביאו תוכנית מימוש של issue ב-GitHub (שפורסמה ע"י `/plan-issue`) ובצעו אותה מקצה לקצה.

**שימוש:** `/implement-issue 42`

## דרישות מקדימות

קראו את `CONTRIBUTING.md` (דלגו אם כבר נקרא בשיחה הזו).

## הוראות

### 1. הבאת ה-issue והתוכנית

המשתמשת מספקת מספר issue כארגומנט.

```bash
gh issue view <number>
gh issue view <number> --comments
```

מצאו את התגובה שמתחילה ב-`## תוכנית מימוש`. זו התוכנית שפורסמה ע"י `/plan-issue`. אם אין תגובת תוכנית, ספרו למשתמשת ועצרו — הציעו להריץ קודם `/plan-issue <number>`.

### 2. תיוג ה-issue

```bash
gh issue edit <number> --add-label "Implementing"
```

### 3. טעינת הקשר

קראו את הקבצים הרלוונטיים שהתוכנית מציינת, ואת כל קובץ נוסף שדרוש כדי להבין את הדפוסים הקיימים (למשל קובץ דומה אחר תחת `js/pages/` או `js/utils/`). התוכנית כבר אמורה להכיל נתיבי קבצים מדויקים — אם משהו חסר או לא ברור, חקרו עם Grep/Glob/Read לפני שמתחילים לממש.

### 4. מימוש התוכנית

בצעו כל שלב בסעיף "שלבים", לפי הסדר. התוכנית מכילה נתיבי קבצים מדויקים, דפוסי קוד והנחיות — עקבו אחריהם במדויק.

- אם שלב מעורפל, השתמשו בשיקול דעת בהתבסס על ההקשר שנטען ודפוסי הקוד הקיימים
- אם שלב נראה שגוי או עלול לשבור משהו, עצרו וספרו למשתמשת לפני שממשיכים
- כבדו תלויות סדר שמצוינות בסעיף "הערות"

### 5. בדיקה

**אל תדלגו על בדיקות.** בניגוד לפרויקטים שרצים ברקע, StudyTop הוא אפליקציה שהמשתמשת פותחת בדפדפן — שינוי שלא נבדק עלול פשוט להיראות שבור אצלה.

- אם הפונקציה שהשתנתה יש לה בדיקה תואמת ב-`tests/`, הריצו/עדכנו אותה (פותחים את דף הבדיקות בדפדפן) וודאו שהיא ירוקה.
- לכל שינוי, בדקו ידנית בדפדפן (דרך `python -m http.server` או Live Server) שהמסך הרלוונטי עדיין עובד — כולל RTL ומצב בהיר/כהה אם רלוונטי.
- אם סעיף "בדיקה" בתוכנית מציין בדיקות נוספות — בצעו גם אותן.

### 6. פרסום דו"ח מימוש ותיוג ה-issue כגמור

פרסמו תגובה על ה-issue עם `gh issue comment`:

```bash
gh issue comment <number> --body "$(cat <<'EOF'
## דו"ח מימוש

### תקציר
<משפט-שניים: מה נבנה/שונה ברמה גבוהה>

### סטיות מהתוכנית
<רשימת נקודות לכל דבר שהיה שונה מהשלבים בתוכנית — גישה אחרת, שלב שדולג, שלב נוסף, קובץ לא איפה שציפו וכו'. אם אין, כתבו "אין.">

### תוצאות בדיקה
<אילו בדיקות רצו (tests/ ו/או בדיקה ידנית בדפדפן) והתוצאה>

### הקשר לביקורת/דיבוג
<כל דבר שסוכן/משתמשת עתידיים צריכים ושלא ברור מקריאת הקוד או התוכנית — החלטות לא-מובנות-מאליהן, מקרי קצה עדינים, דברים שהושארו במכוון לא-שלמים, נקודות תורפה ידועות, קבצים שכדאי לשים לב אליהם>
EOF
)"
```

ואז עדכנו את התווית:

```bash
gh issue edit <number> --remove-label "Implementing" --add-label "Implemented"
```
